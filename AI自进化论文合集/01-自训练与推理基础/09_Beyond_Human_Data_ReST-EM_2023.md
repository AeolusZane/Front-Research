# 超越人类数据：用语言模型扩展自训练以解决问题（Beyond Human Data: Scaling Self-Training for Problem-Solving with Language Models）

> arXiv: 2312.06585 ｜ Avi Singh, John D Co-Reyes, Rishabh Agarwal 等（Google DeepMind / Mila）｜ 2023（发表于 TMLR 2024）

## 摘要（全文翻译）

在人类生成的数据上对语言模型（LM）进行微调是目前的主流做法。然而，此类模型的性能往往受限于高质量人类数据的数量与多样性。本文探讨在能够获取标量反馈信号的任务上（例如数学题可自动验证正确性），能否超越人类数据的限制。为此，我们研究了一种基于期望最大化（expectation-maximization）的简单自训练方法，称为 ReST^EM。其步骤为：（1）从模型中采样输出，用二值反馈信号过滤；（2）在过滤后的样本上对模型进行监督微调；（3）重复上述过程若干次。使用 PaLM-2 系列模型在高难度 MATH 推理基准和 APPS 代码生成基准上进行测试，我们发现 ReST^EM 随模型规模呈现良好的扩展性，并显著超越了仅在人类数据上进行微调的方法。总体而言，我们的发现表明，带反馈的自训练可以降低对人类生成数据的依赖。

## 背景与动机

大型语言模型（LLM）在各类语言任务上表现出色，但在复杂问题求解任务（如竞赛级数学、代码生成）中，获取高质量人类标注数据是重要瓶颈——专家知识稀缺，标注成本高昂。

**核心问题**：在存在可自动验证的外部反馈信号（如数学题答案对错、代码是否通过测试用例）时，能否用模型自己生成的合成数据替代人类数据，并实现性能超越？

**核心挑战**：在线强化学习（online RL）方法虽然理论上可行，但对于数百亿参数的 LLM，每次更新策略后重新采样的计算成本过高。ReST^EM 的核心贡献是将数据收集与策略优化解耦，大幅降低了计算成本，同时提供了严格的理论支撑。

## 方法（核心机制）

**理论框架：期望最大化用于强化学习（EM for RL）**

引入二值最优性变量 O，使得"观察到 O=1（获得高奖励）的对数似然"最大化。通过 Jensen 不等式推导 ELBO（证据下界），EM 算法交替执行 E 步和 M 步，且每次迭代可证明 ELBO 单调不减。

**ReST^EM 算法**

将 E 步（Generate，生成）和 M 步（Improve，提升）解耦，形成迭代循环：

**E 步（生成数据集）**：
- 使用当前策略（语言模型）对每个输入上下文（问题）采样大量输出序列（每题 32 个样本，数学；或 64 个样本，代码）
- 用二值奖励函数对输出打分（数学题：答案与标准答案是否匹配；代码：是否通过所有单元测试）
- 过滤：只保留奖励为 1 的正确解
- 为避免简单题目产生过多样本造成不平衡，每题最多保留 10 个正确解

**M 步（微调提升）**：
- 将过滤后的数据集用于监督微调，最小化奖励加权的负对数似然损失
- **关键设计**：每次迭代始终从原始预训练基础模型（base model）重新微调，而非在上一轮微调模型基础上继续，以避免任务特定过拟合，保持迁移泛化能力

重复上述 Generate-Improve 循环若干次（通常 2-3 次）。

**与相关方法的区别**：

| 特性 | ReST^EM | STaR | RFT | 原版 ReST |
|---|---|---|---|---|
| 每轮从基础模型重新微调 | 是 | 是 | 否 | 否 |
| 温度采样探索 | 是 | 否（贪心） | 是 | 是 |
| 使用反向推理（rationalization） | 否 | 是 | 否 | 否 |
| 多次迭代 | 是 | 是 | 否 | 是 |
| 在大规模 LM 上实验 | 是 | 否 | 否 | 否 |

ReST^EM 与 STaR 最大的方法差异：STaR 使用贪心解码（每题仅一个生成结果）并引入反向推理；ReST^EM 使用温度采样（每题多个解）但不用反向推理（作者发现反向推理会产生大量"答案正确但推理错误"的假阳性样本）。

## 实验与结论

**模型**：PaLM-2 系列（Google Cloud 公开 API）：
- PaLM 2-S（Bison）
- PaLM 2-S*（Codey，代码专项）
- PaLM 2-L（Unicorn）

**数据集**：
- **Hendrycks MATH**：7,500 道竞赛级数学题，按难度分级（AMC/AIME等风格）
- **APPS（Introductory）**：2,342 道代码生成题，以测试用例判断正确性

**主要实验结果**：

*数学推理（MATH）*：
- PaLM 2-S 基础模型：约 25%，经 ReST^EM 3 轮迭代后：约 31%（提升约 6%）
- PaLM 2-L 基础模型：约 34%，经 ReST^EM 3 轮迭代后：约 41%（提升约 6.3%）
- 模型越大，提升效果越显著（与 Yuan et al. 的发现相反，他们在 GSM8K 上观察到大模型收益递减）

*代码生成（APPS Introductory）*：
- 主要收益集中在第 1 轮迭代，多轮后出现性能回退（训练集过拟合，因 APPS 仅 2,342 题约为 MATH 的 1/3）

*迁移学习（Transfer）*：
- MATH 微调后，GSM8K 测试：从约 65% 提升到约 80%；多数模型在匈牙利高中数学决赛考试中表现优于 GPT-3.5，仅次于 GPT-4
- APPS 微调后，HumanEval 迁移显著提升（约 45% → 55%）
- BBH（BIG-Bench Hard）：MATH 微调模型在思维链提示下整体轻微提升，无明显倒退

*模型生成数据 vs 人类数据*：
- 控制变量实验（相同问题数量、每题一个解）：模型生成数据优于人类数据
- 作者推测原因：模型生成的解法分布与模型本身的分布更匹配（"同分布"），而人类解法存在风格差异

*蒸馏实验*：
- 用 PaLM 2-L 生成的数据对 PaLM 2-S 微调（跨模型蒸馏）：超越了用人类数据训练 PaLM 2-S 的效果，也优于 PaLM 2-S 自我生成的 ReST^EM 数据

**关键规律**：
- 多次迭代优于单次迭代（即使单次采样等量数据）
- 仅需约 1,000 道训练题即可获得显著提升（样本效率高）
- 迭代过于多轮（3+ 轮）在 APPS 等小数据集上导致过拟合

**局限性**：
1. 需要一组训练问题（prompts），对新任务仍需人工收集
2. 需要可自动计算的奖励函数（限制了适用范围）
3. pass@1 性能大幅提升，但 pass@K（K 较大时）仍有提升空间
