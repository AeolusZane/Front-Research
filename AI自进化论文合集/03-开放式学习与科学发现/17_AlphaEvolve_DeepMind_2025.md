# AlphaEvolve：面向科学与算法发现的编程智能体（AlphaEvolve: A Coding Agent for Scientific and Algorithmic Discovery）

> arXiv: 2506.13131 ｜ Alexander Novikov, Ngân Vũ, Marvin Eisenberger 等（Google DeepMind）｜ 2025

## 摘要（全文翻译）

在本白皮书中，我们介绍 AlphaEvolve，一种进化式编程智能体，能在高难度任务上显著增强当前最优 LLM 的能力，例如攻克公开科学问题或优化关键计算基础设施。AlphaEvolve 编排一套由 LLM 组成的自主流水线，其任务是通过直接修改代码来改进算法。借助进化方法，持续接收来自一个或多个评测器的反馈，AlphaEvolve 迭代改进算法，潜在地引领新的科学与实际发现。我们通过将其应用于一系列重要计算问题，展示了该方法的广泛适用性。在优化 Google 大规模计算栈的关键组件方面，AlphaEvolve 开发了更高效的数据中心调度算法，在硬件加速器的电路设计中发现了等效简化，并加速了支撑 AlphaEvolve 本身的 LLM 的训练过程。此外，AlphaEvolve 发现了在数学和计算机科学的一系列问题上超越当前最优解的、经过严格验证的新算法，显著扩展了先前自动发现方法（Romera-Paredes et al., 2023）的范围。值得注意的是，AlphaEvolve 开发出一种搜索算法，找到了一种仅用 48 次标量乘法即可完成两个 4×4 复数矩阵相乘的程序，这是 56 年来首次在该设定下超越 Strassen 算法。我们相信 AlphaEvolve 及其同类编程智能体能够在改进科学与计算领域众多问题的解决方案方面产生重大影响。

## 背景与动机

**问题**：发现高价值新知识（如科学发现或商业价值算法）通常需要漫长的构思、探索、回溯、实验与验证过程。尽管 LLM 在代码生成与推理上已展示惊人能力，但要让 LLM 流水线真正做出全新科学发现或实际改进，仍面临巨大挑战——LLM 可能产生幻觉，单次推理缺乏系统性搜索能力。

**核心洞察**：对于能够自动评测的问题（数学、算法设计、系统优化），可以让 LLM 持续生成代码修改提案，并以自动评测结果作为反馈，驱动进化式改进。只要评测函数能机器计算，LLM 的幻觉就会被过滤掉，搜索过程可以无限延续。

**与 FunSearch 的关系**：AlphaEvolve 是 DeepMind 此前发布的 FunSearch（Romera-Paredes et al., 2023）系统的重大增强版本。核心区别在于：FunSearch 只进化单个 Python 函数（10-20 行），而 AlphaEvolve 可进化整个代码文件（数百行，支持任意编程语言）；FunSearch 使用小型代码专用 LLM，AlphaEvolve 使用前沿 LLM（Gemini 2.0 系列）并提供丰富上下文与反馈。

## 方法（核心机制）

**任务规范（Task Specification）**

用户需提供：
1. **评测函数**（evaluate）：Python 函数，接收生成的算法程序为输入，返回一个或多个标量评测指标（规定为最大化方向）。评测可从秒级计算到数小时大规模并行运算。
2. **初始程序**：标注了待进化代码块的完整代码文件（用 `# EVOLVE-BLOCK-START` / `# EVOLVE-BLOCK-END` 注释标记），其余骨架代码固定不变。
3. **可选配置**：自定义提示指令、问题背景（包括论文 PDF）、随机化模板等。

**提示采样（Prompt Sampling）**

从程序数据库中采样已有解程序（包含历史高分方案和多样化探索方案），与当前待改进程序一同构成丰富的上下文提示。支持以下增强：
- 显式上下文：问题背景、方程、代码片段、相关文献
- 随机化格式：多种提示模板变体，增加多样性
- 渲染的评测结果：程序及其执行输出与得分
- **元提示进化**（Meta prompt evolution）：用额外 LLM 调用生成改进提示本身的指令，与解程序并行进化

**创造性生成（Creative Generation）**

LLM 核心角色：消化历史解信息，提出多样化的改进思路。输出格式为 diff 块（SEARCH/REPLACE 格式），支持对代码特定位置的精准修改，也支持完整重写。

模型配置：**Gemini 2.0 Flash**（低延迟，高吞吐，驱动大量候选生成）+ **Gemini 2.0 Pro**（高质量，偶尔提供关键突破性建议）的集成使用。

**评测（Evaluation）**

- **评测级联**（Hypothesis testing）：先在简单测试集上快速淘汰劣解，通过才进入更难测试集，大幅提升效率
- **LLM 生成反馈**：难以量化的性质（如代码简洁性）可用额外 LLM 调用评分，纳入进化指导
- **并行评测**：支持在评测集群上分布式异步评估（如从多随机初始化运行搜索算法）
- **多目标优化**：同时优化多个指标，有助于生成更多样化的高质量候选，即使只关心其中一个指标，多目标优化往往也能提升该指标

**进化数据库（Program Database）**

融合 MAP-elites 算法与岛屿种群模型，平衡探索与开采——持续提升最优程序的同时，维持程序多样性，防止种群坍缩至单一解。

**分布式流水线**：基于 asyncio 的异步计算流水线，包含控制器、LLM 采样节点和评测节点，以最大化在给定计算预算内评估的方案数量为目标优化吞吐量。

## 实验与结论

**一、矩阵乘法算法发现**

**目标**：找到张量秩最小的分解算法（即所需标量乘法次数最少的矩阵乘法算法）。初始输入为标准基于梯度的算法（包含 Adam 优化器）。

**结果**：AlphaEvolve 在 16 种矩阵乘法目标上均改进了当前最优（见主文 Table 2 局部）。最重要发现：
- **4×4 复数矩阵乘法**：将所需标量乘法从 Strassen 递归算法的 49 次降至 **48 次**，这是 56 年来首次在此设定下突破 Strassen 算法
- 对所有参数 m,n,p ≤ 5，AlphaEvolve 均与或超过最优已知解

AlphaEvolve 引入了高度非平凡的改进，包括：优化器从 Adam 改为 AdamW、梯度噪声添加、循环退火梯度裁剪阈值、"幻觉损失"（hallucination loss，随机替换部分参数值以增强探索）、离散化损失（鼓励解接近整数或半整数）等——这些创新共经历 15 次突变迭代产生。

**二、开放数学问题**

在 50 余个数学构造问题上（横跨分析、组合、数论、几何等），AlphaEvolve：
- 约 75% 的问题：重新发现了最优已知构造
- 约 20% 的问题：发现了严格优于最优已知构造的新结果（即突破了 SOTA）

具体突破包括：
- **Erdős 最小重叠问题**：建立了新的上界（优于此前最优纪录）
- **11 维亲吻数问题（Kissing number）**：找到 593 个同时接触中心单位球的不重叠单位球配置，超越此前纪录 592

**三、优化 Google 计算生态系统**

*3.1 数据中心调度（Borg 调度器）*：
AlphaEvolve 从现有生产调度算法出发进行进化，发现了一个极其简洁有效的启发式评分函数（见原文 Figure 6，仅 8 行代码），综合考虑 CPU 和内存的残差比以及二者的交叉项。部署到全球 Google 机队后，持续回收平均 **0.7%** 的原本被"搁置"的算力资源。相比深度强化学习方案，AlphaEvolve 的代码方案在性能相近或更优的同时，具有更强的可解释性、可调试性和可部署性。

*3.2 Gemini 内核优化（Pallas 矩阵乘法分块策略）*：
对 Gemini 训练中关键矩阵乘法算子的分块（tiling）策略进行进化优化。结果：与专家设计的分块启发式相比，**平均提升 23% 的内核运行速度**，整体 Gemini 训练时间缩短 1%。从数月专家工程努力压缩至数天自动实验。该分块启发式已在生产中部署。

*3.3 TPU 硬件电路设计（RTL 优化）*：
对 TPU 矩阵乘法单元中已高度优化的 Verilog 实现进行进化，发现了一处冗余比特可安全移除的简化，经 TPU 工程师验证为正确。虽然下游综合工具也能独立发现该问题，但 AlphaEvolve 在 RTL 阶段的早期发现体现了其在硬件设计流程中的潜力。

*3.4 直接优化编译器生成代码（FlashAttention XLA IR）*：
对 FlashAttention 在 JAX/Pallas 中的实现经 XLA 编译器编译后的中间表示（IR）直接进化优化，无需人类工程师直接编辑 IR。结果：
- FlashAttention 内核本身提速 **32%**
- 前/后处理代码提速 **15%**

**消融实验**：对矩阵乘法和亲吻数问题进行系统消融，以下组件均贡献显著提升（缺少任何一项性能均明显下降）：进化机制 > 上下文提示 > 元提示进化 > 全文件进化 > 强力 LLM。

**局限性**：
- 仅适用于可自动评测的问题，自然科学等实验难以模拟的领域不适用
- LLM 幻觉在无法自动验证的任务上可能成为问题
- 评测函数必须由用户设计，本身仍需人类专业知识
- 当前对无法机器评估的高级想法（如假说层面的创新）支持有限
