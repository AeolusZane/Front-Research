# 达尔文哥德尔机：自我改进智能体的开放式进化（Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents）

> arXiv: 2505.22954 ｜ Jenny Zhang\*, Shengran Hu\*, Cong Lu, Robert Lange, Jeff Clune（英属哥伦比亚大学 / Vector Institute / Sakana AI）｜ 2025（发表于 ICLR 2026）

## 摘要（全文翻译）

当今大多数 AI 系统受限于人类设计的、固定的架构，无法自主且持续地改进自身。另一方面，科学方法是一种累积式、开放式的系统，每一项创新都建立于先前成果之上，从而推动未来的发现。人们越来越希望当前这种手动推进 AI 的过程能够实现自动化。若能安全完成，这种自动化将加速 AI 的发展，使我们能更早地享受其带来的益处。这一前景引出了一个问题：AI 系统如何在不断提升自身能力的同时，越来越善于解决实际问题？元学习（meta-learning）可以自动发现新算法，但受限于一阶改进以及需要人工设计合适的搜索空间。哥德尔机（Gödel machine，Schmidhuber，2007）提出了一种理论上的替代方案：一种以可证明有益的方式反复修改自身的自我改进 AI。然而在实践中，证明大多数变更是净收益的（net beneficial）几乎不可能实现。我们提出达尔文哥德尔机（Darwin Gödel Machine，DGM），这是一种新颖的自我改进系统，它迭代地修改自身代码（同时也提升修改自身代码库的能力），并使用编程基准对每次变更进行经验验证。受达尔文进化论和开放式研究的启发，DGM 构建了一个已生成编程智能体的档案库（archive）。它从档案库中采样智能体，智能体通过自我修改创造新的、更有趣的自身版本。这种开放式探索形成了一棵不断增长的多样化、高质量智能体树，并允许并行探索搜索空间中的多条不同路径。在实验上，DGM 自动提升了其编程能力（如更好的代码编辑工具、长上下文窗口管理、同伴互评机制），在 SWE-bench 上的性能从 20.0% 提升至 50.0%，在 Polyglot 上从 14.2% 提升至 30.7%。此外，DGM 显著优于缺乏自我改进或开放式探索能力的基准方法。所有实验均在安全预防措施下进行（如沙箱隔离、人工监督）。总体而言，DGM 代表了迈向自我改进 AI 的重要一步，能够沿着一条通向无尽创新的路径自主积累垫脚石。所有代码在 https://github.com/jennyzzt/dgm 上开源。

## 背景与动机

**问题**：科学进步是累积且开放式的，每次突破都站在无数先前洞见的肩膀上。然而，当今 AI 系统大多受限于人类设计的固定架构，无法自主改写自身代码——每次 AI 进步依然高度依赖人类干预。

**理论先驱——哥德尔机**：Schmidhuber（2007）提出了哥德尔机（Gödel Machine），一种以形式证明验证每次代码改写是否有益的理论框架。但问题在于，在没有严格假设的条件下，实践中几乎不可能形式化证明一次修改是否净有益。

**DGM 的核心思路**：放弃不切实际的形式证明要求，转而使用**经验验证**——在编程基准上测试，以实验结果作为进化的选择标准。同时借鉴达尔文进化论，维护一个多样化的历史解的档案库作为"垫脚石"，避免陷入局部最优。

**为什么以编程为载体**：编程是一种图灵完备的通用能力，修改智能体代码本身就是一项编程任务，因此编程基准上的性能提升直接反映了系统自我改进能力的提升——这构成了一个自洽的自我参照改进循环。

## 方法（核心机制）

**整体架构**

DGM 从单一初始编程智能体出发，通过迭代循环构建并扩充一个智能体档案库：

1. **父代选择**：从档案库中选择一个父代智能体。选择概率大致正比于性能得分，反比于已有子代数量（倾向于开采高性能且被低度探索的智能体），但所有智能体保有非零选择概率，确保任何改进路径都有可能被探索。

2. **自我修改（Self-Modification）**：被选中的父代智能体分析自身在基准评测上的日志，提出下一个要实现的特性，并将该特性描述作为问题陈述交给自身执行。智能体读取、修改并提交自身的代码库，生成一个新的子代智能体。

3. **评测**：新生成的子代智能体在编程基准上进行定量评测：
   - 第一阶段：10 个任务，验证基本代码编辑功能是否保持
   - 第二阶段：50 个任务，更全面评估性能
   - 第三阶段（仅 SWE-bench）：若前两阶段表现优异，再评测 200 个任务

4. **存档**：通过功能验证的子代智能体（能够编辑代码库）加入档案库；功能受损的智能体被丢弃。

**开放式探索的关键价值**：档案库中被暂时看似"不优"的智能体也可能是重要垫脚石。实验中多次观察到：某次自我修改使性能短暂下降，但后续基于该分支的探索最终发现了性能显著优于所有祖先的版本。

**两条对比基准**：
- **DGM without self-improve**（无自我改进）：复现 ADAS 风格，元智能体始终固定为初始基础智能体，不随时间改进。
- **DGM without open-ended exploration**（无开放式探索）：只保留当前最新一代，始终在最新版本基础上修改（类似爬山算法），功能受损则回退到最近的有效版本。

**初始智能体配置**：极度轻量——仅有两个工具（Bash 执行工具 + 文件查看/编辑工具），以便清晰展示自我改进效果。推理阶段使用 Claude 3.5 Sonnet（New）（SWE-bench）或 o3-mini（Polyglot）；自我修改阶段使用 Claude 3.5 Sonnet（New）。

## 实验与结论

**基准测试**：
- **SWE-bench Verified**：Python 代码库修复任务（GitHub issue → 代码补丁），共选用人工验证的可解任务子集。
- **Polyglot**：多语言编程任务（C++、Rust、Python 等），相比 SWE-bench 更冷门，不易出现数据泄露，且允许评估跨语言泛化能力。采用 pass@1（不使用标准测试用例反馈），不同于 Polyglot 官方排行榜的 pass@2。

**主要结果（80 轮迭代）**：

| 指标 | 基础智能体 | DGM 最优智能体 |
|---|---|---|
| SWE-bench Verified（子集） | 20.0% | **50.0%** |
| Polyglot（全集） | 14.2% | **30.7%** |

DGM 在 SWE-bench 上的最优发现智能体性能与当时检验过的开源人类设计 SoTA 相当，在 Polyglot 上则大幅超越专门为 Polyglot 调优的 Aider 工具。

**消融实验**：
- 去掉自我改进：初期有所提升，但很快饱和，总体显著弱于 DGM
- 去掉开放式探索：陷入局部最优更频繁，总体显著弱于 DGM
- 两个组件均不可或缺

**DGM 自动发现的改进（部分举例）**：
- 文件查看从全文查看升级为按行区间查看（更精准）
- 文件编辑从整文件替换升级为字符串精确替换
- 任务求解增加多次尝试与同伴评估排序机制
- 超出上下文长度时自动摘要

**迁移性**：
- **跨模型**：SWE-bench 用 Claude 3.5 Sonnet 搜索到的最优智能体，迁移到 Claude 3.7 Sonnet 后性能达 59.5%（vs 基础智能体的 19.0%）；迁移到 o3-mini 后达 33.0%（vs 23.0%）。
- **跨基准**：在 SWE-bench 上搜索到的最优智能体，无需任何调整地应用于 Polyglot，性能从基础的 14.2% 提升至 28.9%；反之亦然。
- **跨编程语言**：仅在 Python 任务上搜索的智能体迁移到其他语言仍显著优于 Aider。

**安全措施**：所有智能体在沙箱环境中运行（隔离、严格时限、有限网络访问）；保留完整档案库作为可审计的修改谱系；代码仅限于修改自身 Python 代码库；实验期间未发现恶意行为。

**局限性**：
- 单次 SWE-bench 运行约需 2 周 + 高额 API 费用
- 当前 DGM 不修改基础模型（FM）权重本身（仅优化工具与工作流）
- 仍低于闭源商业 SoTA（如 Claude Sonnet 企业版解决方案）
- 开放式探索过程本身（档案库维护、父代选择策略）目前是固定的，不参与自我改进
